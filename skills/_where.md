The CLI is `{GM}`, relative to the repository root: run it from there (in a linked worktree it is under the main repository's `.git`). It is git, run inside the user's memory repository (`{GM} doctor` says where it is), so any git command works; use only add, commit, mv, rm and read-only ones, and never push, reset or rewrite history unless the user asks. It is created per machine by `git-memory agent init {AGENTS}`.

**If `{GM}` does not exist** ("No such file or directory", "command not found"), git-memory is not set up on this machine yet. Do not work around it and do not touch the memory files by hand. Check whether the binary is installed (`command -v git-memory`, or `Get-Command git-memory` on Windows), then tell the user what is missing and how to fix it, and ask whether you should do it for them:
- binary installed: `git-memory agent init {AGENTS}` (naming the agent to set up), run from the repository root, sets this project up (hooks, commands and the CLI launcher).
- binary not installed: install it first, then run `git-memory agent init {AGENTS}`. On Linux: `curl -fsSL https://github.com/Rickedb/git-memory/releases/latest/download/install.sh | sh`. On Windows (PowerShell): `irm https://github.com/Rickedb/git-memory/releases/latest/download/install.ps1 | iex`. It installs into the user's home directory, needs no root, and may need a new shell before `git-memory` is on the PATH.

Run those commands only after the user says yes; if they decline, stop. Once `{GM} doctor` works, carry on with what the user asked. If the CLI exists but `{GM} log` says the repository "does not have any commits yet", that is not an error: the memory is just empty.
